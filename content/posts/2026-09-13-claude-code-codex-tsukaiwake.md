Mac一台でAI開発を自動化したい人が最初にぶつかる疑問が「Claude CodeとCodex、結局どっちを使えばいいの?」というものです。この記事では実際の使い分け方針を、具体的な作業タイプ別に整理します。

## 結論: 目的で使い分ける

- **既存コードベースの理解・大規模リファクタ・複数ファイル横断の変更** → Claude Code
- **単発のスクリプト生成・アイデアのプロトタイピング** → どちらでも大差なし、慣れている方でOK
- **CIやターミナル操作を伴う自動化パイプライン** → 両方をシェルスクリプトから呼び出して併用するのが最速

一つのツールに固執せず、タスクの粒度で切り替えるのが一番ムダがありません。

## 実例: このブログの自動投稿パイプライン

このブログ自体、以下のような構成で自動化されています。

```bash
scripts/generate_post.py   # Claude APIで記事を1本生成
scripts/build_site.py      # Markdown -> 静的HTMLに変換
scripts/post_to_x.py       # 公式APIでXに告知(任意)
```

`launchd` で毎朝実行し、記事生成からGitHubへのpushまでを無人で回しています。人が介在するのは「読んで軽く手直しする」ところだけです。

## 受託案件で使うときの注意点

クライアント案件でAIコーディングツールを使う場合は、次のチェックリストを必ず確認してください。

- [ ] APIキーやトークンをリポジトリにコミットしていないか(`.gitignore`で除外)
- [ ] 生成コードのライセンス・著作権上の懸念がないか
- [ ] 自動投稿系の機能が対象プラットフォームの利用規約に違反していないか
- [ ] 本番環境に触れる自動化は必ずドライラン・レビューを挟む

特に「非公式APIでのSNS自動投稿」はアカウント凍結リスクが高いため、公式APIの範囲内に留めるのが鉄則です。

## まとめ

Claude CodeとCodexはどちらか一方を選ぶものではなく、タスクの性質に応じて併用するのが最も生産的です。自動化パイプラインを組む際は、規約順守とキー管理を最優先にしましょう。
